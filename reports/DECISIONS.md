# Decision log

All decisions stay within the approved scope; none required sponsor approval. Dates are 2026-11-12.

| # | Decision | Why | Contract impact | Tests |
|---|---|---|---|---|
| D1 | **pnpm monorepo, TypeScript strict, packages consumed as source** (no per-package build) | Fast iteration; Vite and tsx consume TS directly; one `tsc --noEmit` typechecks everything | Matches TECH_STACK package boundaries (`layout` folded into `renderers`) | `pnpm typecheck` |
| D2 | **Resolver is a pure isomorphic package used by both browser and API** | Instant local re-resolution for spatial views; identical semantics for exports | Satisfies "pure resolver" invariant; runIds deterministic | 12 goldens incl. byte-identical `resultDigest` |
| D3 | **`result.diagnostics` keeps the oracle's exact shape; richer findings live in `findings`** | `verify_app.py` compares diagnostics by strict equality | Additive fields only | Golden + verify_app |
| D4 | **Paged composition = DOM measurement by an in-browser paginator running in headless Chromium**, then `page.pdf()` | ADR-004 permits explicit page grouping with measured heights; avoids Paged.js uncertainty | Page count is the composer's page tree; independently cross-checked by counting PDF page objects | AT-18/19, Page Stack `PDF verified N` |
| D5 | **Fixed elements that intersect the flow region shrink that page's flow region** (FIXED_FLOW_ADJUSTED warning) rather than text-wrapping | "Cannot silently overlap" with bounded POC complexity | Documented limitation | Composer diagnostics |
| D6 | **Document fonts use the Arial stack (Liberation Sans here); UI uses Inter** | Brand guide specifies Arial for documents; Inter OTF alternates produced unmapped PDF glyphs (amounts not extractable) | Improves PDF text fidelity | AT-24/28 text extraction |
| D7 | **Additive `showSection` targets are modelled as rule-driven Conditional Region nodes** (and materialised from content parts if not a node) | Keeps them visible/selectable in the editor and explodable | Seed node IDs preserved; selectedVariants still only lists Variant Sets (oracle parity) | Golden tests |
| D8 | **Conditional Region (C10) = ordered branches with typed inline conditions, exclusive or additive, optional fallback** | Gives C10 genuine behaviour distinct from C11 | Inline evaluations appear in the trace as `inline-condition` | Unit AT-07 model test + E2E |
| D9 | **Undo/redo = immutable snapshots (immer); every undo/redo is itself a new model version** | Monotonic modelVersion for optimistic concurrency; dirty = content digest ≠ saved digest | `PUT` with `If-Match` | API conflict test |
| D10 | **Exports from unsaved drafts**: the client posts the current model; the API validates it (schema + every rule) and records an immutable run | Hero path requires editing → exporting without forcing saves; still "compose from a recorded run" | Run table stores the exact request | AT-29 (draft compose), API tests |
| D11 | **`contentDigest` is content-addressed** (excludes model version counter and producer) | Reset increments versions; deterministic replay must compare content | Digest semantics documented | AT-36 identical digests |
| D12 | **Issued journey snapshots are write-once rows (sha256 of canonical manifest + HTML), verified on every read** | ADR-006 immutability, provable | `alreadyIssued`, `verified` flags | API test, AT-21 |
| D13 | **Member liability guard**: unconfirmed `patientResponsibilityCents` is rendered "Not determined — under review", excluded from money facts, and debt wording raises UNCONFIRMED_DEBT_LANGUAGE | EOB rule "never infer $300 owed" | New domain finding code | AT-29 |
| D14 | **Spanish copy is not pre-translated in the seed** | Golden `card-spanish-missing-mandatory-translation` requires the blocking error; fixing it = adding an approved translation in the content editor | Spanish personas show a real D02 defect until translated | AT-20 |
| D15 | **Offline assistant = deterministic grammar; live adapter = official `@anthropic-ai/sdk`, model `claude-opus-5-5`, effort `low`, server-side refusal fallback (`fallbacks: "default"`), tool output re-validated with zod** | Spec requires a working fallback; Claude is the supported provider in this codebase | No browser keys; any provider failure → offline | AT-30/31/32 (offline); live path unverified |
| D16 | **InfoSlips brand tokens applied (greens, slate scale, Inter UI / Arial documents); no logo artwork bundled** | Brand pack in this environment provided palette/typography only; brand rules forbid redrawing the logo | `--iss-logo-url` slot ready for the official asset | Visual review |
| D17 | **Functional warning/error colours retained** (amber/coral) alongside brand greens | Diagnostics must be unambiguous; red/amber are status semantics, not decoration | Documented in tokens.css | — |
| D18 | **Exported HTML is CSP-locked, script-inline, asset-free** | Offline, no tracking, safe to share | — | AT-25, renderer tests |
| D19 | **Test hook `window.__iss` (read-only store + digest)** | Lets acceptance tests assert model digests without UI scraping | No secrets; synthetic data only | All E2E |
| D20 | **Model orchestration**: Opus led architecture, model, resolver, composer, API, store, Design, Exploded, Gallery, Demo, tests and integration; four Claude Sonnet 5.5 subagents built eight screens against `docs/dev/AGENT_BRIEF.md` with strict file ownership | Parallelism without contention on shared architecture | Project agent definitions in `.claude/agents/` (Sonnet/Haiku/Fable); they were created mid-session and not loadable by name, so the built-in general-purpose agent was used with `model: sonnet` | Integrator reviewed and re-verified every screen in its own E2E suite |
| D21 | **Haiku and Fable were not used** | No low-value repetitive chores worth delegating; no problem remained unresolved after a serious Opus attempt (pagination worked first time), so escalation was not justified | — | — |
| D22 | **Vite optimizer cache per dev-server port; all `@tiptap/*` pinned to 2.27.3** | Parallel dev servers invalidated each other; mixed tiptap minors broke pre-bundling | — | — |
| D23 | **Polish pass (v0.2): Business/Technical view, light theme default, compact headers, single disclaimer** | Stakeholder review found the UI engineer-facing and cramped. Business view re-words rules as sentences (`ui/plain.ts`) and puts run IDs/hashes/raw expressions behind *Proof* disclosures; nothing is removed. Spatial stages stay dark in both themes by re-scoping dark tokens | Population counts (reach, clusters, cube totals, impact) keep the word *synthetic* as required by PRODUCT_SPEC (AT-16, "clearly marked synthetic count"); other repeated disclaimers removed; persistent top-bar badge kept | AT-01…36, F01 |
| D24 | **Status dock mirrors the server's rules + bindings suites** (same pure functions, in the browser), or the full validation result once run for the current scenario | Removes conflicting blocking counts between the dock and Validate & Compare | Validate groups checks that share a rule pair as one issue ("2 checks agree") but keeps raw counts available | F09 |
| D25 | **User projects**: duplicate (version 1, `derivedFrom`), rename, delete; approved samples are restorable but never deletable | Needed to experiment without touching the approved samples | New `/projects/:id/duplicate`, `PATCH`, `DELETE` | API + F03 |
| D26 | **Imported records** (CSV/JSON) are validated against the project data contract, re-identified `CARD-5xxx`/`EOB-5xxx`, stored locally, flagged `imported`; CSV columns are matched to fields in the browser | Lets users test designs against their own (synthetic/anonymised) data without ever masquerading as fixtures | UI warns: synthetic or anonymised data only; nothing leaves the machine | API + F04 |
| D27 | **Custom data fields** live on the project (`customFields`, paths `custom.<key>`) and flow through the same contract checks as standard fields (rules, bindings, resolver, import); removing a field in use is refused | Keeps runs deterministic (the contract travels with the model digest) | Command `SET_CUSTOM_FIELDS` (undoable) | Unit + F05 |
| D28 | **Impact preview** = pure `impactOf(before, after, records)` in `@iss/scenarios` (2 resolves per record, memoised, debounced) | "What changes for whom" before applying rule/condition edits | ~170 ms for 70 records in Chromium | Unit + F06 |
| D29 | **Batch runs** compose sequentially on the shared headless Chromium and package PDFs/HTML + `manifest.json` + `run-report.csv` into a ZIP (in-house writer on `node:zlib`); blocked records are skipped unless watermarked drafts are requested | Shows production-style throughput and failure reporting with the same engine | 70 records PDF+HTML ≈ 20 s locally | API + F07 |
| D30 | **Image library**: PNG/JPEG/WebP only (magic-byte check), ≤ 280 KB, content-addressed; picking embeds a data URI in the model so exports stay self-contained and CSP-locked; SVG refused | Safe, reusable artwork without breaking asset-free exports | Browser downscales large images before upload | API + F08 |
| D31 | **Docker**: Microsoft Playwright 1.63 base image (Node + matching Chromium), production web build, data in a volume, port bound to 127.0.0.1 | One-command run on Windows/macOS without Node/pnpm/Python/browser setup | Not a deployment; local only | Built and smoke-tested (health, PDF compose, web) |
| D32 | **Cross-platform scripts** (`run-python.mjs`, `verify-all.mjs`, `shell` on Windows spawns) and optional local `.env` loaded by the API | Windows users hit PowerShell/`python3`/bash gaps | `pnpm verify` replaces `verify-all.sh --app` (the shell script remains) | Ran on Linux; Windows untested here |
